SYSTEM OVERVIEW
================================================================================

The Sales Module is a complete sales management system that handles the entire 
customer-to-order workflow:

1. CUSTOMER: The starting point. Stores customer information, contact details, 
   segment classification (VIP/Regular), and all communication history with the 
   customer in a single place.

2. QUOTATION: An initial price proposal created for a customer. Think of it as 
   a "draft order" or "quote". The sales team sends quotations to customers, 
   who can accept or reject them. Each quotation tracks discount, tax, and 
   expiration date.

3. SALES ORDER: A confirmed order. When a customer accepts a quotation, it gets 
   converted into a Sales Order. This is the final confirmed request that moves 
   to processing, shipping, and invoicing.

HOW THEY WORK TOGETHER:
  Customer initiates inquiry
       ↓
  Create QUOTATION (linked to Customer)
       ↓
  Customer reviews quotation
       ↓
  If accepted: Convert QUOTATION → SALES ORDER (both linked together)
       ↓
  If rejected/expired: Close quotation, create new one if needed
       ↓
  SALES ORDER moves through: pending → processing → completed
       ↓
  Track all communication with Customer via communication logs

Each table maintains referential integrity so you can trace the entire 
customer journey from the first quote to the final order.


================================================================================
TABLE 1: QUOTATION
================================================================================

Description: Initial price proposals sent to customers before order confirmation.
Status Flow: draft → sent → accepted → converted to order | rejected | expired

Fields:
  _id, customerId, productId, quantity, discount, tax, totalAmount, status, 
  validUntil, convertedToOrderId, createdAt, updatedAt

API Endpoints:
  GET     /api/quotations                    | Fetch All
  GET     /api/quotations/:id                | Fetch One
  POST    /api/quotations                    | Create
  PUT     /api/quotations/:id                | Update
  DELETE  /api/quotations/:id                | Delete
  POST    /api/quotations/:id/convert        | Convert to Order
  POST    /api/quotations/:id/reject         | Reject Quotation


================================================================================
TABLE 2: SALES ORDER
================================================================================

Description: Confirmed orders created from accepted quotations or directly created.
Status Flow: pending → processing → completed | cancelled

Fields:
  _id, quotationId, customerId, productId, quantity, discount, tax, 
  totalAmount, status, shippingAddress, createdAt, updatedAt

API Endpoints:
  GET     /api/salesorders                   | Fetch All
  GET     /api/salesorders/:id               | Fetch One
  POST    /api/salesorders                   | Create
  PUT     /api/salesorders/:id               | Update
  DELETE  /api/salesorders/:id               | Delete
  POST    /api/salesorders/:id/invoice       | Generate Invoice
  POST    /api/salesorders/:id/credit-check  | Check Credit


================================================================================
TABLE 3: CUSTOMER
================================================================================

Description: Customer profiles with contact info, segment classification, and 
communication history.

Fields:
  id, name, email, phoneNumber, address, segment, preferences, createdAt, 
  communicationLogs[]

API Endpoints:
  GET     /api/customers                     | Fetch All
  GET     /api/customers/:id                 | Fetch One
  POST    /api/customers                     | Create
  PUT     /api/customers/:id                 | Update
  DELETE  /api/customers/:id                 | Delete
  POST    /api/customers/:id/logs            | Add Communication Log
  PUT     /api/customers/:id/logs/:logId     | Update Log
  DELETE  /api/customers/:id/logs/:logId     | Delete Log


================================================================================
KEY RELATIONSHIPS
================================================================================

Quotation → SalesOrder: One quotation can be converted to ONE sales order 
                        (via convertedToOrderId & quotationId)

Quotation → Customer: Many quotations linked to ONE customer (customerId)

SalesOrder → Customer: Many orders linked to ONE customer (customerId)

Customer → CommunicationLogs: One customer has MANY logs (embedded array)


================================================================================
CONVERSION FLOW
================================================================================

1. Create Quotation (status: "draft")
2. Customer views quotation
3. Update Quotation status to "sent"
4. Customer accepts quotation
5. Update Quotation status to "accepted"
6. Call /api/quotations/:id/convert endpoint
   → Creates new SalesOrder
   → Sets Quotation.convertedToOrderId
   → Sets SalesOrder.quotationId
   → Returns new order data

Result: Quotation locked (cannot convert again), SalesOrder ready for processing
